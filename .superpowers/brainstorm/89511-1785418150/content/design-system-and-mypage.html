03 · Feature Readiness

추가 기능을 받을 수 있는 공통 패턴

출시된 기능처럼 과장하지 않고, 백엔드·프론트 단계에 맞춰 준비 중 상태와 실제 사용 상태를 분리합니다.

01Register

실종 소식 등록 + 그룹 생성

SEARCHING 등록 때만 수색그룹을 만들고 참여 방식을 함께 선택합니다.

  • 자유롭게 참여 기본값
  • 승인 후 참여 선택 가능
  • SEEN/FOUND에는 그룹 없음
프론트 연결 예정
02Group & Team

개인·팀의 함께 찾기

개인은 바로 참여할 수 있고, 지속형 팀 하나가 여러 실종 소식을 지원합니다.

  • 보호자만 전체 수색 종료
  • 팀장은 우리 팀 지원만 종료
  • ADMIN 역할 없음
백엔드 브랜치 구현
03Map & Notification

통합 지도와 구조화 알림

권한 있는 활성 소식·목격만 지도에 모으고 승인·제보·종료를 알립니다.

  • 실종 지점은 붉은 계열
  • 목격은 푸른 계열
  • 사람 위치는 수집하지 않음
지도 Phase 2
04Chat & Share

그룹 대화와 공개 공유

수색그룹당 기록형 대화방 하나를 두고, 카카오톡은 공개 실종 소식 링크를 공유합니다.

  • 종료 후 대화 읽기 전용
  • 비밀 초대 링크 아님
  • SDK 실패 시 링크 복사
채팅 Phase 3
04 · Compatibility Migration

기존 기능을 깨지 않는 적용 순서

두 곳으로 나뉜 UI primitive와 하드코딩 색상을 한 번에 교체하지 않고, semantic token과 adapter를 먼저 둡니다.

호환 레이어 원칙

현재 `src/components/ui`를 표준으로 잡되 `src/app/_components/ui`는 즉시 삭제하지 않습니다. 기존 Button 크기·variant를 명시한 뒤 화면별로 이전하고, 전단지 인쇄색·카카오 노랑·지도 상태색은 일반 primary 토큰과 분리합니다.

이 디자인 시스템을 구현 기준으로 확정할까요?

확정하면 다음 단계에서 이 구조를 설계 명세로 기록하고, 검토 후 기존 기능을 보존하는 화면별 구현 계획을 작성합니다.
