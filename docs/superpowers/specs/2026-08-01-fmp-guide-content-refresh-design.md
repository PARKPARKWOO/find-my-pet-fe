# Find My Pet 안내·정적 콘텐츠 통합 개편 설계

**작성일:** 2026-08-01

**상태:** 사용자 설계 승인 완료, 구현 전

**대상:** `/guide`, `/faq`, 기존 `/posts` 정적 글, 홈 안내 카드, 실종 상세·전단지의 정적 안내, 검색·AI 인용용 정적 사실

**제품 기준:** `prd/find-my-pet/requirements.md`, `prd/find-my-pet/api-spec.md`, `prd/find-my-pet/search-radius-and-flyer.md`, `docs/superpowers/specs/2026-07-30-fmp-full-site-design-system-design.md`

---

## 1. 결정 요약

현재 웹의 `/posts`는 `src/posts/*.mdx` 정적 자료실이지만, 사용자 등록 실종 소식은 백엔드와 RSS에서 `post`로 불리고 화면에서는 `/lost`에 노출된다. 같은 단어가 두 종류의 콘텐츠를 가리켜 사용자가 `/posts`를 등록 게시글 목록으로 오해할 수 있다.

이 개편은 다음처럼 역할을 분리한다.

- `/guide`: 실종·발견·보호소 반환·입양·예방을 묶는 한 단계 안내 허브
- `/guide/{slug}`: 상황별 상세 안내
- `/faq`: 질문에 바로 답하는 `상황별 반려동물 안내`
- `/lost`, `/lost/{id}`: 사용자가 등록한 실종·목격 소식
- 기존 `/posts` 정적 자료실 URL: 대응하는 `/guide` URL로 영구 이동

새 `/resources` 허브는 만들지 않는다. 정보 깊이를 늘리지 않고 기존 `/guide`를 확장한다.

## 2. 문제 정의

### 2.1 이름과 정보 구조 충돌

- 웹 `/posts`는 정적 MDX 글 목록이다.
- API `/api/v1/posts`와 `/rss.xml`의 `post`는 사용자 등록 실종 소식이다.
- 사용자 화면은 같은 대상을 `/lost`와 `실종 소식`이라고 부른다.
- `/posts`는 전역 내비게이션·푸터에서 직접 연결되지 않아 사실상 고립돼 있다.

### 2.2 중복과 사실 불일치

- `/guide`와 `dog-missing-guide.mdx`가 같은 실종 대응 내용을 별도로 보유한다.
- `/guide`의 화면 본문, HowTo JSON-LD, FAQ JSON-LD가 각각 하드코딩돼 서로 어긋날 수 있다.
- `동물보호관리시스템`과 `국가동물보호정보시스템` 명칭이 혼용된다.
- 일반 실종 상황에 경찰·119 신고를 일괄 권하는 문구, 체취 물품이 행동 반경을 제한한다는 문구, 내장칩이 반환 확률을 크게 높인다는 문구처럼 현재 근거를 확인하지 못한 주장이 있다.
- 보호 공고 최소 7일과 공고일부터 10일 후 지방자치단체의 소유권 취득 가능성을 `공고 후 10일`로 합쳐 설명하는 정적 사실이 있다.
- 고양이 글에 강아지 목줄·하네스 안내가 복사돼 있다.

### 2.3 화면·접근성·검색 결함

- `/posts` 목록과 상세에 의미 있는 H1, 완전한 canonical·Article metadata가 없다.
- 존재하지 않는 정적 글이 실제 404가 아니라 200 응답의 `Not Found` 문구를 반환한다.
- 카드 링크와 버튼이 중첩되고, 반복 항목 key와 이미지 대체 텍스트가 빠진 곳이 있다.
- 모바일 고정폭과 12px 링크 텍스트가 있다.
- 정적 글의 sitemap `lastModified`가 콘텐츠 검토일이 아니라 빌드 시각으로 바뀐다.
- IndexNow의 정적 글 수집 범위와 실제 MDX 파서의 재귀 수집 범위가 다르다.

### 2.4 제품 사실과 안내 문구 충돌

- 수색그룹·팀은 기능 브랜치에만 있고 현재 프론트에 연결되지 않았다.
- 제품 내 그룹 채팅과 그룹·팀 통합 지도는 아직 구현 전이다.
- 탐색 범위는 참고용 추정치이며 개의 도로망 계산이 실패하면 원형으로 후퇴할 수 있다.
- AI 유사 후보는 기본 설정에서 비활성인데 빈 상태가 실제 비교를 수행한 것처럼 말한다.
- 종료된 `FOUND` 소식에도 활성 수색 전략이 계속 노출될 수 있다.
- 전단지 페이지는 텍스트 초안을 브라우저 저장소에 보관하면서 `입력한 내용은 저장되지 않는다`고 안내한다.

## 3. 목표와 비목표

### 3.1 목표

1. 실종 직후 사용자가 첫 행동을 빠르게 찾게 한다.
2. 발견 동물 신고·인계, 보호소 반환, 보호소 입양 방법과 절차를 같은 안내 허브에서 찾게 한다.
3. 정적 자료와 사용자 등록 소식의 URL·이름을 분리한다.
4. 화면, JSON-LD, 홈 카드, `llms.txt`가 같은 사실을 말하게 한다.
5. 공식 출처, 마지막 검토일, 지역별 차이를 명확히 표시한다.
6. 기존 외부 링크와 검색 신호는 영구 이동·canonical로 보존한다.
7. 기존 디자인 시스템과 한 단계 탐색 원칙을 유지한다.

### 3.2 비목표

- 수색그룹·팀·제품 내 채팅·통합 지도를 이번 작업에서 구현하거나 출시 기능처럼 소개하지 않는다.
- `/shelters`, `/adoption/wanted`, `/adoption/offer`의 새 백엔드 계약이나 게시판을 만들지 않는다.
- 보호소 입양 신청을 FMP 안에서 처리하지 않는다.
- 법률·수의학·행동학 자문을 대체한다고 표현하지 않는다.
- 이용약관·개인정보처리방침 본문을 일반 안내 콘텐츠처럼 다시 쓰지 않는다. 깨진 링크·기능 사실만 별도 근거가 있을 때 최소 수정한다.
- 사용자 등록 실종 소식의 `/lost` URL을 `/posts`로 바꾸지 않는다.

## 4. 확정 용어

| 내부·제도 개념 | 사용자 문구 |
|---|---|
| User post | 실종 소식 또는 목격 소식 |
| FMP post creation | 실종 소식 등록 |
| Government loss report | 지자체·동물보호센터에 유실 신고 |
| Shelter notice | 보호 공고 |
| Adoption | 입양 |
| Guide hub | 반려동물 안내 |
| FAQ route | 상황별 반려동물 안내 |
| Search radius | 탐색 범위 또는 참고용 탐색 범위 |
| Search group | 수색그룹 — 구현 전 콘텐츠에서는 현재 기능으로 소개하지 않음 |

`분양`보다 기존 목적 카테고리와 맞는 `입양`을 기본 용어로 쓴다. 법령이나 공식 원문을 설명할 때만 `유실·유기동물`, `분양` 같은 제도 용어를 필요한 범위에서 병기한다.

## 5. 경로와 이전 정책

### 5.1 새 공개 경로

| 경로 | 역할 |
|---|---|
| `/guide` | 전체 안내 허브와 실종 직후 핵심 행동 요약 |
| `/guide/lost-dog` | 반려견 실종 첫날 체크리스트 |
| `/guide/dog-walk-safety` | 산책 중 이탈 예방 |
| `/guide/cat-escape-prevention` | 고양이 탈출 예방과 초기 확인 |
| `/guide/found-animal` | 길에서 헤매는 동물을 발견했을 때 신고·인계 |
| `/guide/shelter-adoption` | 보호소 입양 준비와 일반 절차 |
| `/faq` | 상황별 질문과 답변 |

보호소에서 내 반려동물을 확인한 뒤의 반환 절차는 `/faq#shelter-return`을 SSOT로 유지하고 `/guide` 카드에서 해당 앵커로 연결한다. 내용이 독립 장문 안내가 필요해지는 시점에만 별도 경로를 추가한다.

### 5.2 영구 이동

| 기존 경로 | 목적지 | 이유 |
|---|---|---|
| `/posts` | `/guide` | 정적 자료실 허브 이전 |
| `/posts/dog-missing-guide` | `/guide/lost-dog` | 기존 글의 역할 축소·개편 |
| `/posts/dog-escape-while-walking` | `/guide/dog-walk-safety` | 더 직접적인 안내명 사용 |
| `/posts/cat-escape-reasons-and-solutions` | `/guide/cat-escape-prevention` | 예방 중심으로 재작성 |

영구 이동은 Next의 `permanent: true` redirect(308)로 처리하고 새 페이지 canonical만 sitemap·IndexNow에 포함한다. API `/api/v1/posts`와 최근 사용자 실종 소식을 내보내는 `/rss.xml`은 변경하지 않는다.

기존 홈·검색 링크를 깨뜨리지 않도록 `/guide`의 실종 직후 요약에 호환 anchor `수색`과 `전단지`를 모두 유지한다. 새 내부 링크는 영문 안정 ID를 사용하되 기존 두 공개 anchor는 제거하지 않는다.

## 6. 정보 구조

### 6.1 전역과 로컬 탐색

전역 내비게이션의 64px 한 줄 구조와 `이용 안내` 항목은 유지한다. `/guide` 안에서만 다음 한 단계 링크를 제공한다.

- 잃어버렸을 때
- 상황별 질문
- 안내 글 모아보기

중첩 사이드바나 다단 드롭다운은 만들지 않는다. 데스크톱은 짧은 가로 링크, 모바일은 한 열 또는 가로 스크롤 없는 줄바꿈 링크로 제공한다.

### 6.2 `/guide` 허브 순서

화면 H1은 `반려동물과 함께할 때 필요한 안내`로 확정한다. 설명은 `잃어버렸을 때부터 발견·보호소 반환·입양·예방까지, 상황에 맞는 순서를 확인하세요.`를 기본안으로 사용하고 `content-ops` 평가에서 같은 의미 안에서만 다듬는다.

1. 제목과 위 한 문장 설명
2. `반려동물을 잃어버렸을 때, 지금 할 일` 핵심 요약
3. 주요 행동
   - `실종 소식 등록` → `/register`
   - `보호 공고 확인` → `/abandonment/region`
   - `전단지 만들기` → `/flyer`
4. 상황 카드
   - 반려동물을 잃어버렸을 때
   - 길에서 헤매는 동물을 발견했을 때
   - 보호소에서 내 아이를 찾았을 때
   - 보호소 입양을 준비할 때
   - 산책 중 이탈을 예방할 때
   - 고양이의 탈출을 예방할 때
5. 공식 확인처와 마지막 검토일
6. 상황별 질문 연결

허브의 핵심 실종 요약은 `src/content/lostGuide.ts`의 단계 배열에서 렌더링한다. 각 단계는 안정 ID, 제목, 짧은 요약, 상세 설명, 행동 링크, 출처를 가진다. `/guide`는 같은 배열의 제목·짧은 요약·행동만 보여주고 `/guide/lost-dog`는 상세 설명과 반려견 callout을 더해 보여준다. HowTo JSON-LD도 이 배열의 화면 노출 단계에서 생성한다. 별도 문장 복사나 두 번째 단계 배열은 만들지 않는다.

### 6.3 `/faq` 그룹과 기존 anchor

기존 10개 공개 ID를 보존한다.

| 그룹 | ID |
|---|---|
| 잃어버렸거나 발견했어요 | `shelter-check`, `missing-report`, `found-animal-report`, `search-radius` |
| 보호소에서 내 아이를 찾았어요 | `shelter-return`, `notice-period`, `after-notice` |
| 입양·등록을 준비해요 | `adoption-process`, `animal-registration` |
| 파인드마이펫 데이터가 궁금해요 | `data-source` |

기존 flat 목록의 DOM 순서는 유지 대상이 아니다. 위 그룹 안의 순서로 의도적으로 재배치하되 공개 ID와 hash URL은 그대로 보존한다. 계약 테스트도 legacy 배열 순서 대신 그룹·ID·anchor 호환성을 고정한다.

화면 H1은 `상황별 반려동물 안내`를 유지한다. `FAQ`는 URL, metadata 검색어, FAQPage 구조화 데이터에만 남길 수 있으며 독립적인 화면 label로 강조하지 않는다.

답변은 첫 문장에서 직접 답하고, 뒤에 예외·지역 차이·다음 행동을 쓴다. 중요한 답을 클라이언트 JavaScript가 있어야만 볼 수 있는 구조로 숨기지 않는다.

### 6.4 상세 안내 역할

#### 반려견 실종 첫날

- 즉시 주변 확인
- 지자체·동물보호센터 유실 신고
- 국가동물보호정보시스템 보호 공고 반복 확인
- FMP 실종 소식 등록과 공개 링크 공유
- 전단지 준비와 안전한 반복 수색
- 찾은 뒤 소식 종료

정확한 성공률, 보장된 행동 반경, 모든 개에게 같은 수색법을 제시하지 않는다.

#### 발견 동물 신고·인계

- 사람과 동물의 안전을 먼저 확인
- 무리한 포획·접촉을 일반 행동으로 권하지 않음
- 관할 지자체 또는 동물보호센터 연락처 확인
- 목줄·인식표 확인은 안전할 때만 수행
- FMP의 공개 실종 소식과 대조
- 판매·임의 소유·신원 공개 위험을 경고

#### 보호소 입양 준비

- 보호 공고 종료가 곧 입양 가능을 뜻하지 않음
- 보호소에 현재 상태와 신청 가능 시점 확인
- 신청서·상담·교육·방문 등은 보호소마다 다름
- 가족·주거·비용·돌봄 계획을 사전에 확인
- 지원금은 지역별 조건이 달라 해당 지자체에 확인
- FMP는 입양 신청을 받지 않고 보호소 연락 경로만 제공

#### 예방 안내

- 산책 장비와 문·창문 환경을 구체적으로 점검
- 강압적 훈련이나 검증되지 않은 단일 요령을 만능 해법처럼 제시하지 않음
- 고양이 동물등록은 의무 등록 대상인 개와 구분
- AirTag와 GPS 위치 추적기를 같은 기능으로 표현하지 않음
- 행동 변화나 극심한 불안은 수의사·적절한 전문가 상담을 안내

## 7. 사실 기준과 출처

### 7.1 제품 사실 우선순위

1. 운영에서 직접 검증된 기능 — 공개 화면에서 `현재 제공`으로 표현 가능
2. 같은 미리보기 변경 묶음에 포함되고 검증된 프론트·백엔드 계약 — 해당 미리보기 안에서만 설명 가능
3. 미병합 기능 브랜치·설계 문서 — `준비 중` 또는 향후 계획으로만 표현

`현재 제공` 같은 공개 출시 표현은 운영에서 확인된 기능에만 쓴다. 같은 변경 묶음에 포함돼 검증된 로컬 기능은 미리보기 안에서 설명할 수 있지만 운영 출시 사실로 확대하지 않는다. 수색그룹·팀 백엔드 기능 브랜치는 프론트 미연결이므로 현재 기능으로 소개하지 않는다. 카카오톡 공유는 공개 실종 소식·보호 공고 링크 공유까지만 설명하고 그룹 초대 링크로 표현하지 않는다. 현재 알림은 목격 제보·즐겨찾기 상태 변경·관심 지역 새 보호 공고 범위로 제한한다.

## 8. 연결된 정적 문구 보정

### 8.1 탐색 범위

- `실제 동물 위치`나 `찾을 확률이 높은 정확한 범위`가 아니라 참고용 추정치로 설명한다.
- 종·품종·경과시간을 입력으로 사용한다.
- 개는 도로망 도달 영역을 우선 시도하고 계산 실패 시 원형으로 표시할 수 있다.
- 고양이·기타는 원형 참고 범위를 사용한다.
- 개체 성향, 지형, 목격 정보, 보호 공고 확인을 함께 보도록 안내한다.
- 14일 이후 AI가 더 효과적이라는 근거 없는 문구를 제거한다.

### 8.2 AI 유사 후보

- 기능이 비활성인 상태와 실제 비교 결과 0건을 같은 성공 문구로 표현하지 않는다.
- 현재 상태를 구분할 수 없으면 `오늘 비교했다`, `내일 다시 찾는다` 같은 실행 사실을 만들지 않는다.
- 기본 비활성 환경에서는 구성요소를 숨기거나 `현재 비교 기능을 제공하지 않습니다. 보호 공고를 직접 확인해 주세요.`처럼 사실만 말한다.

### 8.3 완료된 수색

`FOUND` 소식에는 경과시간 경고, 활성 탐색 범위, 장기 수색 전략, AI 후보를 노출하지 않는다. 완료 상태에는 기록 확인과 다시 찾은 소식에 맞는 중립 안내만 제공한다.

### 8.4 전단지

- 실제 동작을 유지한다면 `입력한 글은 이 기기의 브라우저에 임시 저장될 수 있으며 서버로 전송하지 않습니다. 사진은 저장하지 않습니다.`처럼 설명한다.
- 사진이 실제 인쇄 활성화 조건이 아니라면 필수 표시를 제거하고 강한 권장으로 표시한다. 행동 변경이 필요하면 별도 요구사항으로 분리한다.
- `A4 한 장` 고정 문구 대신 사용자가 선택한 용지와 인쇄 설정을 확인하도록 안내한다.
- 게시 전 시설·관리자의 부착 허가와 공개 연락처 범위를 확인하도록 안내한다.
- 실제 제3자 전화번호가 포함된 `guide_5.png`와 오래된 외부 서비스 화면 캡처는 노출하지 않는다.

### 8.5 홈·지역 페이지·크롤러 사실

- 홈 상황 카드의 제목·설명·링크를 새 guide catalog에서 가져온다.
- `/abandonment/region/**`의 `자주 묻는 질문` 링크는 사용자 노출명 `상황별 반려동물 안내`로 맞춘다.
- `public/llms.txt`의 `공고 후 10일`, `매시간`, `/posts` 자료실 URL을 바로잡는다.
- sitemap과 IndexNow는 새 `/guide` URL을 사용하고 MDX/guide catalog와 같은 수집 범위를 사용한다.
- RSS는 사용자 등록 실종 소식 피드이므로 `/lost/{id}` 링크 계약을 유지한다.

## 9. 콘텐츠·코드 경계

### 9.1 권장 모듈

- `src/content/guideCatalog.ts`
  - 허브 카드, 경로, 제목, 설명, 사용자 행동, 검토일
- `src/content/faq.ts`
  - 기존 10개 ID, 그룹, 질문, 답변, `reviewedAt`, 내부·공식 링크
- `src/content/lostGuide.ts`
  - 허브 실종 요약과 HowTo 상세 단계의 SSOT
- `src/guides/*.mdx`
  - 상세 안내 본문
- `src/lib/parseGuide.ts`
  - 필수 frontmatter 검증과 안전한 slug 생성

기존 `featuredGuides.ts`와 `parsePost.ts`는 새 역할에 맞춰 대체하거나 얇은 호환 모듈로 축소한다. 기능이 다른 모든 콘텐츠를 하나의 거대한 파일에 넣지 않는다.

각 FAQ 항목은 `reviewedAt`을 필수로 갖는다. 법률·정책·입양·동물 행동처럼 외부 사실을 답하는 항목은 `{ label, url }` 형태의 `sourceLinks`도 필수다. FMP 제품 동작만 설명하는 항목은 공개 화면에 내부 저장소 경로를 노출하지 않고 계약 테스트가 제품 코드·PRD 근거와의 일치를 검증한다. FAQ 화면과 FAQPage JSON-LD는 이 같은 항목 배열에서 생성한다.

### 9.2 필수 guide metadata

- `title`
- `subtitle`
- `description`
- `publishedAt`
- `updatedAt`
- `reviewedAt`
- `sourceLinks`
- `slug`

`publishedAt`은 최초 발행일, `updatedAt`은 본문이 의미 있게 바뀐 날, `reviewedAt`은 외부 기준을 마지막으로 확인한 날이다. 원문을 전면 개편해도 최초 발행일을 새 날짜로 가장하지 않고 `updatedAt`을 함께 표시한다. sitemap `lastModified`와 Article `dateModified`는 `updatedAt`을 사용한다.

`sourceLinks`는 `{ label, url }` 객체 배열이다. `thumbnail`과 `thumbnailAlt`는 선택 필드지만 둘 중 하나만 존재할 수 없다. 이미지가 있으면 출처·라이선스 또는 생성 이력을 asset provenance에 기록하고 문맥에 맞는 alt를 제공한다. 검증 가능한 provenance가 없으면 새 이미지를 억지로 넣지 않고 텍스트 카드나 공통 브랜드 fallback을 사용한다.

필수값 누락, 잘못된 날짜, 중복 slug는 빌드 또는 계약 테스트에서 실패시킨다. 빈 값으로 조용히 색인하지 않는다.

### 9.3 화면과 JSON-LD

- `/guide`: `CollectionPage`를 사용하고 실제 노출 카드의 `ItemList`를 `mainEntity`로 포함
- 순서형 상세 안내: 화면과 같은 단계에서 HowTo 생성
- `/faq`: 같은 FAQ 레지스트리에서 화면과 FAQPage 생성
- guide 상세: Article metadata, canonical, 선택 대표 이미지, 최초 발행일·수정일·검토일

구조화 데이터에 화면에 없는 질문·답변·단계나 근거 없는 기능을 추가하지 않는다.

### 9.4 오류 처리

- 존재하지 않는 guide slug는 `notFound()`로 실제 404를 반환한다.
- 외부 출처가 일시적으로 열리지 않아도 페이지 렌더링은 유지하되, 발행 전 검증 실패로 기록한다.
- 영구 이동 대상 외의 알 수 없는 `/posts/*` 경로를 임의로 비슷한 글에 연결하지 않는다.

## 10. UI·접근성

- 기존 `canvas`, `paper`, `raised`, `ink`, `forest`, `clay` 토큰을 사용한다.
- 안내 본문은 약 720–760px의 읽기 폭과 16px/1.6 이상의 본문 행간을 사용한다.
- 페이지마다 H1은 하나만 둔다.
- 주요 행동은 44px 이상의 터치 영역과 분명한 focus-visible 상태를 제공한다.
- 링크 안에 버튼을 넣지 않고 하나의 interactive element만 사용한다.
- 외부 링크는 목적을 label에 드러내고 새 탭이면 `rel="noopener noreferrer"`를 적용한다.
- 의미 없는 emoji 번호와 장식용 아이콘 반복을 제거한다.
- 대표 이미지에는 문맥을 설명하는 대체 텍스트를 둔다. 장식 이미지는 빈 alt로 분리한다.
- 실종 직후 핵심 행동은 accordion이나 JavaScript 뒤에 숨기지 않는다.
- JavaScript가 없어도 허브, 상세 본문, 내부 링크, 공식 출처를 읽을 수 있다.
- 390px·768px·1440px에서 가로 overflow와 지나치게 긴 카드 높이를 확인한다.

## 11. `content-ops` 전문가 패널

### 11.1 패널 구성

|---|---|

| 국내 동물보호 법령·정책 검증자 | 공고 기간, 소유권, 동물등록, 신고 표현 |
| 보호소·입양 절차 검토자 | 반환·입양 가능 시점과 지역 차이 |
| 쉬운 한국어 UX·정보구조 라이터 | 짧고 직접적인 문장, 행동 label, `/guide`·`/faq` 역할과 한 단계 탐색 |
| 접근성 검토자 | heading, link, 읽기 순서, 모바일 터치 |
| SEO·구조화 데이터 검토자 | canonical, redirect, JSON-LD, 중복 콘텐츠 |
| 개인정보·전단지 안전 검토자 | 연락처·사진·브라우저 저장·부착 안내 |
| 브랜드 보이스 일치 검토자 | FMP의 부드럽고 직접적인 말투와 누적 승인·거절 패턴 |
| AI 문체 감별자 | 과장, 상투어, 기계적 목록, 불필요한 emoji 등 AI 문체 패턴 |

AI 문체 감별자 점수는 1.5배로 가중한다.

### 11.2 합성 평가 기준

정적 도움말은 일반 아티클과 행동 페이지의 성격을 함께 가지므로 content-quality와 conversion-quality 기준을 합성한다.

| 항목 | 배점 |
|---|---:|
| 사실·안전성 | 30 |
| 행동 명확성 | 20 |
| 자연스러운 문체 | 15 |
| 정보 가치·구체성 | 15 |
| 정보구조·접근성 | 10 |
| 검색·출처 신뢰성 | 10 |

다음 중 하나라도 있으면 해당 라운드는 90점 미만으로 제한한다.

- 근거 없는 법률·의료·행동학 단정
- 미출시 기능을 현재 기능처럼 소개
- 보호 공고 종료를 동물의 최종 상태로 단정
- FMP 등록을 공식 유실 신고처럼 표현
- 실제 개인정보 노출 또는 저장 동작과 다른 안내
- 화면과 JSON-LD의 질문·답변·단계 불일치

모든 전문가 점수와 가중 평균이 각각 90점 이상이 될 때까지 최대 3회 반복한다. 매 라운드 전에 `content-ops/references/patterns.md`를 확인한다. 각 라운드는 전문가별 점수표, 가중 평균, 상위 약점 3개, 구체적인 변경 내용과 그 라운드의 수정본을 남긴다. 최종 출력은 Winner+Score를 먼저 보여주고 전체 패널명·반복 횟수·모든 scoring history를 함께 제공한다.

3회 뒤 하나라도 90점 미만이면 가장 나은 문안과 남은 위험을 정직하게 보고하고 구현을 승인 상태로 표현하지 않는다. 사용자가 90점 이상 결과를 거절하거나 패널 판단을 덮어쓰면 거절 이유를 확인해 `content-ops/references/patterns.md` 형식으로 선호·거절 패턴과 감점 규칙을 기록한다.

## 14. 완료 조건

- `/posts` 정적 자료와 사용자 등록 소식의 이름 충돌이 공개 경로에서 사라진다.
- `/guide`에서 실종·발견·반환·입양·예방 안내를 한 단계로 찾을 수 있다.
- 기존 정적 글 URL은 모두 정확한 새 URL로 영구 이동한다.
- FAQ ID와 외부 anchor 호환성이 유지된다.
- 화면·JSON-LD·홈 카드·`llms.txt`가 같은 사실을 사용한다.
- 공고 7일/소유권 10일, 동물등록, FMP 등록과 공식 신고, 공고 종료 의미가 구분된다.
- 미출시 수색그룹·팀·채팅·통합 지도를 현재 기능처럼 표현하지 않는다.
- `content-ops`의 모든 전문가 점수와 가중 평균이 각각 90점 이상이거나, 3회 뒤 남은 위험을 명시하고 구현 보류 상태로 보고한다.
- 접근성·SEO·redirect·404·모바일 검증이 통과한다.
- 운영 배포는 변경되지 않는다.
